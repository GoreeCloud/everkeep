# Everkeep — Specifications

## Status

**Lifecycle:** Development  
**Canonical repository:** `GoreeCloud/everkeep`  
**Platform Contract:** 0.4  
**Current shared Glaze UI consumer target:** 1.6.0  
**Production acceptance:** not established  
**Stable qualification:** not established

## Role

Everkeep is GoreeCloud's platform-wide resilience, recovery, preservation, portability, continuity, succession, digital-legacy, and recovery-assurance authority. It is not a backup engine, storage platform, secret store, or generic remediation API.

## Implemented source foundation

The current repository provides machine-readable continuity contracts, evidence models, resource and protection-policy foundations, recovery-point and verification services, persistence boundaries, recovery planning, Recovery Center projections, restore-test scheduling, preservation and portability models, succession eligibility, continuity objectives, recovery topology, failover governance, simulation-only controlled drill execution, rollback assurance, and minimized signal-delivery adapters.

Implemented Development source must not be represented as live production recovery capability without exact target and workload evidence.

## Authority boundaries

- GoreeCloud Identity owns identity, authentication, authorization, credentials, and trust.
- Privacy Shield owns privacy, retention, deletion, export, transfer, and data-use constraints.
- Wardveil Security owns security, integrity, threat findings, and security acceptance.
- GoreeCloud Manager owns platform administration and management surfaces.
- GoreeCloud Mesh owns coordination and bounded evidence transport.
- GoreeCloud Policy owns shared cross-domain policy representation and coordination when an accepted runtime contract exists.
- GoreeCloud Observability owns shared operational telemetry and health correlation when an accepted runtime contract exists.
- Glaze UI owns presentation and interaction requirements.
- GoreeCloud Sync remains separately governed and cannot substitute for backup or recovery evidence.

## Recovery truth

Everkeep distinguishes backup existence from verified recoverability. A recovery-ready claim requires current, authoritative, scope-correct evidence for every applicable required dimension. Missing, stale, malformed, unavailable, conflicting, or unverified required evidence fails closed.

## Current blockers

Live authority-provider connectivity, real per-workload isolated restore evidence, production Monitoring/Notify acceptance, current-contract Continuity Center acceptance, controlled production failover/rollback, application-specific production continuity acceptance, deployment/rollback verification, release approval, and Stable qualification remain open.
